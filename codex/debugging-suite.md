## DEBUGGING_SUITE

**Core Philosophy**: Building great code isn't about throwing out bad code and restarting. It's about iterating bad code into good code into great code.

Trigger this when the user says "Debug this" or "This feels flat." Do not just rewrite; run the 5-Part Diagnostic:

### 1. Does the code even compute?

**Look for logical flow**:
- Does the logic flow from Zeitgeist → Tension → Insight → Role → CTA → Strategy?
- Does it tell a complete story?
- After removing what doesn't work, what empty steps are you left with?

**Common issues**:
- Word salad or vague statements
- Missing connections between steps
- Sections that sound right individually but don't connect

**Action**: Mark problematic sections. Keep what works. Identify gaps.

### 2. Is the output close to expectation?

**Does it fulfill the objective?**:
- Does the strategy actually deliver on the campaign's objective?
- Does the brand even have a role in this story?
- Is this a halo topic that's on-brand?

**Common issues**:
- The CTA doesn't align with the brand's USP
- The Role isn't connected to the brand's actual superpower
- Off-brand territory

**Action**: Check if the work is even in the right ballpark. If not, tweak or remove problematic parts.

### 3. Is there similar code to compare to?

**Cross-reference versions**:
- Do you have another version or perspective from someone else?
- Different backgrounds = different POVs = more diverse ideas
- Can you combine the best parts of multiple versions?

**Action**: Compare versions side-by-side. Pick the strongest elements from each. Ask: "Do you have any other versions or examples to compare?"

### 4. Is the content in the right step?

**The "Wrong Step" problem**:
- Think about the definition of each framework step
- Does the writing fit the definition of the step it's in?
- Is there a line in the wrong step that actually sounds more like an Insight? Or a CTA that's really a Role?

**Debugging technique**:
- Start with the Insight (usually the heart of the issue)
- See if content from other steps sounds more like an Insight
- Move it, rewrite it, then work backwards and forwards to restore flow

**Common issues**:
- CTA language that's actually describing the Insight
- Tension that's actually Zeitgeist (or vice versa)
- Role that's actually the Strategy

**Action**: "There is something here. I think this sounds more like an [X]." Move it. Rewrite. Rebuild flow.

### 5. Is the code efficient?

**Make it lyrical**:
- You made it logical. Now make it sing.

**The refinement process**: Cut. Cut. Rephrase. Concise. Cut. Cut more.

**Common issues**: Overwritten language, corporate jargon creeping back in, unnecessary qualifiers.

**Action**: Ruthlessly edit for concision and poetry.

---

**The Complete Process**:
1. First, make it **Logical** (fix the code)
2. Then, make it **Lyrical** (make it sing)

**Starting questions**:
- "Do you have any other versions or examples to compare?"
- "Do you have references or past work that could inspire us?"
